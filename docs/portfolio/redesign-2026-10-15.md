# Portfolio product studio redesign

## Authorization and sequence

The October 15 owner request authorizes a full aesthetic revision, motion, and truthful navigable project previews. The recorded July 14 `APPROVE PHASE 1` remains valid. Existing verified career facts and approved download bytes remain the content baseline.

Work proceeds section by section: live evidence audit; opening/navigation; project interfaces; supporting sections; responsive and accessibility review; static export; release verification.

## Design thesis

The subject is a hands-on technical founder working across scientific software, operational systems, and learning products. The audience needs to understand what he builds by using it. Lead with work, with deeper context after it. Move the long biography and personal video below the projects; retain their anchors and content.

Palette: instrument silver `#edf1f5`, paper `#fafbfd`, carbon `#17212e`, cobalt `#2749db`, deep blue `#14296b`, signal ice `#b9e5ff`. Dark mode uses blue-black `#101725` with readable silver surfaces. Syne provides expressive display type; Geist carries body text; Geist Mono labels real product state.

Layout: a compact name/role and a large editorial thesis beside a sculptural signal field; a quiet project index followed by wide interactive product windows; alternating compact editorial sections for research and professional context.

```
name / role        Work · About · Research · Contact
large thesis      interactive signal sculpture
work action       field mode / pause
-------------------------------------------------
project narrative | usable product window
project narrative | usable product window
-------------------------------------------------
research artifact | method / contribution
about / portrait  | concise cross-domain story
experience        | dated rows
capabilities      | evidence links
ventures          | explicit roles
education         | degrees and credentials
contact           | draft form and professional links
```

Self-critique: a dark neon dashboard would repeat the current site's decorative framing. Use cool daylight and a cobalt field instead. Remove decorative numbering, duplicated browser chrome, ornamental graphs around text, and repeated playback controls. Make the project itself the interaction. The signature sculpture is a conceptual illustration, never represented as a measured neural dataset.

## Preview contract

- Each project gets one navigable local product sample with real buttons and truthful content.
- The preview states its sample/prototype scope concisely.
- A full-site action opens a verified public app in a new tab; repository actions identify themselves as source.
- Verified embeddable public apps can be opened inside the product window explicitly, with the full-site link always available.
- Never embed a repository page, an authenticated private workspace, or a site whose framing policy rejects the portfolio.
- Preserve actual data provenance and joint authorship.
- No automatic slideshow while a person is operating a preview.

## Acceptance

Review each section visually at 390, 768, 1440, and 1920px. Exercise every project workflow, keyboard focus, reduced motion, no-JavaScript reading, root and GitHub Pages routing, download integrity, crawler metadata, and new-tab actions. Run repository lint, type-check, rendered HTML tests, export/adapter tests and production build. Record evidence and limitations before release.
